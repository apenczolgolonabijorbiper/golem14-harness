03 / Data model
A claim is the unit of knowledge.
Relations are claims whose object references an entity. Every claim retains attribution, exact quotations, time, status and uncertainty.
GRAPH v2 · HYPOTHESES v1
Identity
Source → Entity
Entities cite source UUIDs. Labels and aliases are discovery aids; they never establish identity.
Assertion
Entity → Claim → Object
subject_id and attributed_to_id reference entities. object contains either entity_id or a scalar value.
Review
Claim → Hypothesis
Hypothesis support/refutation reference claims. Claim depends_on and supersedes link claims for different purposes.
Each cited source must appear in the source_ids of the claim's subject, attributed entity and entity-valued object. A quote must occur exactly in that observation's body.
Identity & retained history
  • Source UUID, path, hash and recording time remain unchanged.
  • Entity ID, type, created_at and existing provenance are retained. A stable kind cannot be changed once present.
  • External identifiers are exact, append-only triples: scheme + namespace + value.
  • Prior claims remain intact except for permitted status changes. Superseded/retracted claims cannot be reactivated.
  • A correction creates a new claim with supersedes; dependency and correction cycles fail validation.
Three distinct notions of time
FieldMeaning
recorded_atObservation recording timestamp.
asserted_atExactly copies a cited source's recorded_at, including fractional formatting.
valid_timeEvidenced effective interval, expression and precision.
created_atActual graph-record creation time.
Valid-time filtering uses current correction knowledge. It does not reconstruct the database as it was known at a past transaction time.

Publication invariants

06 / Completed-candidate merge
Combine work. Preserve disagreements.
New in v0.9.0: a mechanical three-way merge of completed snapshots from one common base. Select a synthetic scenario to see the rule.
SINCE 0.8.0
BASE / common snapshot
OURS / fresh owner head
THEIRS / completed candidate
The helper guarantees
  • ID-keyed graph, ledger, questions and hypothesis merging; no field-level reconciliation inside a record.
  • Both branches validate against BASE; combined graph validates against OURS.
  • Existing source, evidence, event and journal bytes remain unchanged.
  • Purpose and selected guidance/configuration must match BASE.
  • Conflicts return JSON and exit 1 without creating OUT.
  • Reports cap warnings/conflicts at 1,000 with truncation metadata.
The host must still publish
  • Authenticate the processor and verify common ancestry and release.
  • Capture coherent immutable snapshots; a live directory is not atomic.
  • Regenerate flagged summaries, review and fully revalidate.
  • Stage a released lease, recheck ownership, source bytes and ledger.
  • Atomically publish against fresh head using compare-and-swap.
  • The reference adapter still commits only its own claimed sources.
OUT is a private review draft. The helper never copies or manages processing-lock.json, leases or Git refs. It does not publish. Host-owned bounded reservations are coordination hints; the reference claim CLI has no reservation exclusion option.
Input & output bounds
64 MiB / input
50k entries / input
128 path components
Fresh OUT path only
OUT must be absent with an existing parent, outside all inputs and engine. Symlinks, nonregular files and nonportable paths are refused. Root .git metadata is ignored.


07 / Policy, retrieval & limits
Bounded behavior. Visible uncertainty.
Profiles guide the agent and configure declarative vocabulary. Core integrity checks remain mandatory.
POLICY v2
Explicit profile activation
{
  "schema_version": 1,
  "profile": {
    "path": "profiles/default.md",
    "vocabulary": "profiles/vocabulary.json",
    "sections": [
      {"id": "notes", "path": "profiles/notes.md", "kinds": ["note"]}
    ]
  }
}
A file existing in profiles/ does not activate it. The selected core is always delivered; configured sections are included in order when their kinds match the batch. Missing or malformed selected files block analysis.
Policy vocabulary
{
  "schema_version": 2,
  "kinds": ["record", "person"],
  "predicates": ["release_state", "describes"],
  "single_valued": ["release_state"],
  "external_id_schemes": [
    {"scheme": "record", "prefixes": ["REC-"]}
  ]
}
Missing lists are unrestricted. Empty lists warn on all populated values. Up to 500 entries per kind/predicate/single_valued list; 100 identifier schemes; 20 prefixes per scheme. Profiles cannot increase engine bounds.
Lexical retrieval
Normalized exact tokens over labels, aliases, IDs, predicates, values and quotes; identifier matching can seed entities. Default ranking adds one related graph hop.
No embeddings
Bounded traversal
Explicit --hops selects deterministic undirected breadth-first traversal over subject/object links. Predicate, type, kind and status filters refine output.
1–3 hops · budget ≤20,000
Temporal policy
--current needs single_valued configuration. Exact effective starts outrank partial/as-reported bounds; latest asserted_at is only a labelled fallback. Ties remain explicit.

Advisory findings vs errors
Warnings request review. Structural, provenance, identity, history and transaction failures block publication. Confidence is an analyst assessment, not calibrated probability. The absence of warnings never establishes truth or independent corroboration.
